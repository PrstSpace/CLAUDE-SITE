# PRST Events — QR-регистрация на мероприятия

Сайт для регистрации участников на мероприятия PRST (стенды на выставках и т.п.)
по QR-коду: посетитель сканирует табличку у стенда → попадает на страницу
регистрации → вводит ФИО, телефон, email, компанию и должность → получает на
почту QR-билет → на входе билет сканирует хостес и отмечает вход.

Данные собираются и хранятся на сервере в РФ (152-ФЗ), письма с билетами
отправляются через Microsoft 365 (Microsoft Graph API).

## Стек

- **Next.js 16** (App Router, TypeScript, Tailwind)
- **PostgreSQL** + **Prisma 7** (через `@prisma/adapter-pg`)
- **Microsoft Graph API** — отправка писем с QR-билетом (client credentials flow)
- **html5-qrcode** — сканер QR на входе (камера в браузере)
- Аутентификация админки — cookie-сессия (JWT, без внешних сервисов)

## Функционал

- `/events/[slug]` — публичная страница регистрации на конкретное мероприятие
- `/admin` — админка: создание/редактирование мероприятий, список регистраций,
  экспорт в CSV, повторная отправка билета
- `/admin/checkin/[eventId]` — сканер QR-кодов для хостес на входе

## Локальная разработка

1. Установите зависимости:
   ```bash
   npm install
   ```
2. Поднимите локальный Postgres (свой, или через Docker):
   ```bash
   docker run -d --name prst-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16-alpine
   ```
3. Скопируйте `.env.example` в `.env` и заполните `DATABASE_URL`, `AUTH_SECRET`
   (и, при наличии, Azure AD credentials — без них письма не будут отправляться,
   но регистрация и вся остальная логика будут работать).
4. Примените миграции и создайте первого администратора:
   ```bash
   npm run db:migrate:dev
   npm run db:seed
   ```
5. Запустите dev-сервер:
   ```bash
   npm run dev
   ```

## Настройка Microsoft 365 / Azure AD (отправка писем с билетом)

Отправка писем идёт через Microsoft Graph API от имени сервисного приложения
(без участия человека), поэтому нужна регистрация приложения в Azure AD с
правами уровня приложения (Application permissions), а не делегированными.

1. Зайдите в [Azure Portal](https://portal.azure.com) → **Azure Active
   Directory** → **App registrations** → **New registration**. Имя — например
   `PRST Events Mailer`, тип — Single tenant.
2. После создания скопируйте **Application (client) ID** и **Directory
   (tenant) ID** — это `AZURE_CLIENT_ID` и `AZURE_TENANT_ID`.
3. **Certificates & secrets** → **New client secret** → скопируйте значение
   (показывается один раз) — это `AZURE_CLIENT_SECRET`.
4. **API permissions** → **Add a permission** → **Microsoft Graph** →
   **Application permissions** → найдите и добавьте `Mail.Send`.
5. Там же нажмите **Grant admin consent for <organization>** — без этого
   право не будет активно (для этого шага нужны права администратора
   тенанта M365).
6. В `.env` укажите `GRAPH_SENDER_MAILBOX` — реальный почтовый ящик в вашем
   M365-тенанте, от имени которого будут отправляться письма (например,
   `events@prst.space`). У приложения с правами `Mail.Send` на уровне
   приложения есть доступ к отправке от имени **любого** ящика в тенанте —
   при необходимости это можно ограничить конкретным ящиком через
   [application access policy](https://learn.microsoft.com/en-us/graph/auth-limit-mailbox-access).

## Деплой на VPS (REG.RU и любой другой)

Проект разворачивается через Docker Compose — работает на любом обычном
Linux-VPS (в частности, на VPS/VDS от REG.RU).

1. На сервере установите Docker и Docker Compose (`docker compose version`
   должен работать).
2. Склонируйте репозиторий на сервер, перейдите в его папку.
3. Скопируйте `.env.example` в `.env`, заполните все значения (пароль БД,
   `AUTH_SECRET`, Azure AD credentials, данные первого администратора).
4. Соберите и примените миграции + создайте администратора (одноразово, и
   при последующих обновлениях схемы):
   ```bash
   docker compose --profile tools run --rm migrate
   ```
5. Запустите приложение:
   ```bash
   docker compose up -d --build app
   ```
6. Настройте reverse proxy (nginx/Caddy) с HTTPS на домен `events.prst.space`,
   проксирующий на порт `3000` контейнера `app`. Пример для Caddy — просто
   `events.prst.space { reverse_proxy localhost:3000 }`, сертификат Let's
   Encrypt Caddy выпустит и обновит сам.
7. Направьте DNS-запись `events.prst.space` на IP сервера (в панели REG.RU,
   где зарегистрирован домен).

После обновления кода: `git pull`, затем при изменениях схемы БД —
`docker compose --profile tools run --rm migrate`, и `docker compose up -d
--build app`.

## Персональные данные (152-ФЗ)

- Все персональные данные (ФИО, телефон, email, компания, должность) хранятся
  только в БД Postgres, поднятой на сервере в РФ — иностранные сервисы для
  сбора/хранения не используются.
- QR-билет кодирует непрозрачный токен, а не сами персональные данные.
- Письма с билетом отправляются через Microsoft Graph API — то есть адрес и
  имя получателя передаются в Microsoft 365. Обратите внимание: это может
  требовать учёта требований о трансграничной передаче персональных данных
  (уведомление Роскомнадзора и т.п.) — уточните этот момент с юристом.
- Текст согласия на обработку персональных данных на странице регистрации и
  политика на `/privacy` — черновики, требуют проверки и утверждения
  юристом компании перед реальным использованием (реквизиты оператора,
  точные формулировки, сроки хранения).

## Структура проекта

```
app/
  events/[slug]/        — публичная страница регистрации
  admin/                — админка (логин, мероприятия, сканер)
  api/admin/            — API: чек-ин, экспорт CSV
  privacy/              — страница политики обработки ПДн
lib/                    — Prisma-клиент, auth, отправка писем, QR, валидация
prisma/                 — схема БД, миграции, seed-скрипт
```
